# Обновления

Swissman се обновява с цели, подписани издания, а не пакет по пакет.

## На компютъра

```sh
swissman-update --check     # има ли ново издание
swissman-update             # изтегли и подготви новото издание
swissman-update --status    # коя версия е инсталирана и какво чака
swissman-update --rollback  # върни предишната версия
```

Обновлението се прилага при следващото стартиране.

### Как работи

1. `swissman-update` тегли `MANIFEST` и `MANIFEST.sig` от последното
   издание в GitHub Releases.
2. Проверява подписа (Ed25519) с ключа на изданията, вграден в системата
   (`/usr/share/swissman/update-keys/`). Ако подписът не е валиден,
   обновлението спира. Ключове, на които имаш доверие, можеш да добавиш в
   `/etc/swissman/update-keys/`.
3. Отказва версия, която не е по-нова от инсталираната, за да не може някой
   да ти подхвърли стара версия с известни пропуски.
4. Тегли образа на системата (`swissman-rootfs.sfs`) и проверява SHA-256
   сумата му от подписания `MANIFEST`.
5. Разопакова новия `/usr` до текущия като `/usr.new`. Нови файлове в `/etc`
   се копират, а твоите настройки остават.
6. Сглобява ново ядро (UKI) от новия `/usr` и го подписва с твоя Secure Boot
   ключ. Старото ядро остава като `swissman-previous.efi`.
7. При стартиране initramfs-ът сменя `/usr.new` с `/usr`, а стария пази като
   `/usr.old`. Смяната е с преименуване, така че прекъсване по средата се
   довършва при следващото стартиране.

`--rollback` връща предишния `/usr` и предишното ядро по същия начин.

Адресът на изданията може да се смени в `/etc/swissman/update.conf`
(`URL=...`) или с `--url`. Може да е и папка на диска.

## Издаване на нова версия (за собственика на репото)

### Веднъж: ключ за подписване

```sh
tools/make-update-key.sh ~/swissman-update.key
git add config/update-signing.pem
git commit -m "Add the release signing key"
```

Публичният ключ (`config/update-signing.pem`) влиза във всяко ISO. Частният
ключ (`~/swissman-update.key`) пази в тайна. Без публичния ключ в репото
GitHub Actions отказва да издаде версия.

Избери как да се подписват изданията:

- **Автоматично в GitHub.** Добави частния ключ като secret
  `UPDATE_SIGNING_KEY` (Settings → Secrets and variables → Actions). Всяко
  издание се подписва и публикува само.
- **На твоя компютър.** Не добавяй secret. GitHub създава издание като
  чернова (draft), а ти го подписваш сам (по-долу). Така никой с достъп до
  GitHub не може да пусне обновление към компютрите ти.

### Всяко издание

```sh
git tag v0.2.0
git push origin v0.2.0
```

GitHub Actions компилира, тества в QEMU и създава издание `v0.2.0` с
`swissman.iso`, `swissman-rootfs.sfs`, `MANIFEST` и `SHA256SUMS`.

Ако подписваш на своя компютър: изтегли `MANIFEST` от черновата и изпълни

```sh
tools/sign-release.sh <папката с MANIFEST> ~/swissman-update.key
```

После качи `MANIFEST.sig` в черновата и я публикувай (Publish release).
